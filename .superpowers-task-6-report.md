## What it does
`OperationHistoryPanel({ operations, dataset })` renders:
- `<div class="operation-history-panel">`
  - A summary header (`.operation-history-summary`) showing the operation count and the **current** dataset's own stats (point count + bbox, via `computeStats` from `src/core/stats.ts`) — shown regardless of history length.
  - If `operations.length === 0`: `<p class="operation-history-empty">No operations yet.</p>`.
  - Otherwise: `<ul class="operation-list">` with one `<li class="operation-item">` per `OperationRecord`, each showing:
    - index, `summary`, and an ISO `<time>` element (`epochMsToIso(createdAt)`, imported from `src/core/format.ts` — deterministic across locales/timezones for both display and tests, unlike `toLocaleString`).
    - `operationId`/`operationVersion` and a flattened `key: value` rendering of `params` (via a local `formatParams` helper — `params` is `unknown` per-operation, so it falls back to `JSON.stringify` for non-plain-object shapes).
    - `scope` (when recorded) rendered as `points #start–end` for `indexRange` or an ISO range for `timeRange`.
    - a `.operation-warnings` list when `operation.warnings` is non-empty.

## Design note on "before/after stats"
`OperationRecord` (in `src/core/recipes/model.ts`) only stores `inputDatasetHash`/`outputDatasetHash` — content hashes, not point-count/range snapshots — and the panel only receives the final `dataset`, not per-step history. A true before/after point-count diff per operation isn't calculable from these inputs. Per the task's "if calculable" qualifier, I implemented what *is* derivable:
- current dataset stats (point count, bbox) in the summary header, and
- per-operation `scope` (index/time range actually touched), when the operation recorded one.

This is documented in a comment on the component itself so a future task wiring in real before/after snapshots (e.g. if `OperationRecord` grows a `pointCountBefore/After` field) has the context.
