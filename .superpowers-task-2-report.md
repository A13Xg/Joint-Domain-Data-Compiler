## Concerns / design decisions

1. **No prior React-component test infrastructure existed.** `scripts/run-tests.mjs` only bundled `test/*.ts` via `esbuild` and ran the result with plain `node`; there was no DOM, no jsdom/happy-dom dependency, and no prior `test/*.tsx` file to pattern-match against. I built the DOM for this test using `linkedom` (already a devDependency, previously only used to patch `DOMParser` for XML parsing in `test/helpers/linkedomShim.ts`) plus `react-dom/client`'s `createRoot`/`flushSync`, assigning `window`/`document`/`navigator`/`requestAnimationFrame`/`cancelAnimationFrame` onto `globalThis` before rendering. This is a real integration test (actual React reconciliation, actual DOM button elements, actual dispatched click events), not a hand-rolled shallow-render — verified empirically before writing the real test.

2. **Fixed a latent JSX bug in the test runner.** `esbuild`'s own tsconfig auto-discovery only reads the root `tsconfig.json` (no `"jsx"` field there — it lives in `tsconfig.app.json`, which esbuild's directory-walk doesn't follow via project references). Bundling `.tsx` files directly with `buildSync` therefore silently fell back to esbuild's classic JSX transform, which compiles `<Foo/>` to a bare `React.createElement(...)` call. Since this repo's other `src/ui/*.tsx` components (e.g. `TimeSeriesChart.tsx`, `InfoTooltip.tsx`) never import `React` — they rely on the automatic runtime configured for the real Vite/tsc build — that would have caused a `ReferenceError: React is not defined` at test runtime for any test that imports a real component. Confirmed this by bundling `src/ui/ChartTypeSelector.tsx` alone and inspecting the output before and after. Fixed by adding `jsx: 'automatic'` to the `buildSync` call in `scripts/run-tests.mjs`, which matches the app's actual JSX runtime and required no changes to any `src/` file's import conventions. This fix affects the shared test runner, so it will also benefit Task 4's `TimeSeriesChart.tsx` tests (or any other future `.tsx` test).

3. **Disabled-click guard is defensive, not required.** The component's `onClick` checks `info.isValid` before calling `onSelectType`, but native disabled buttons generally won't dispatch synthetic click callbacks through React's event system regardless. Kept the explicit guard anyway since it makes the invariant obvious at the call site and doesn't rely on framework/DOM-implementation click-suppression behavior for disabled elements.

4. **`getValidChartTypes` order is relied on for button ordering** (`timeSeries`, `scatter`, `area`, per `validator.ts`) — the test destructures buttons positionally rather than by label/aria-label lookup. If Task 1's validator ever reorders its returned array, this test would need updating; documented via the array-destructuring comments in the test.

5. Reverted an incidental `package-lock.json` diff (optional-dependency `peer`/`resolved` metadata churn from an `npx` invocation during investigation) — not part of this task, left untouched.
